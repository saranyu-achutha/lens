Market Lens: API sample responses

Real responses captured by the application (stored raw responses in the database, plus a few live calls on 2026-10-16). Long lists are cut to the first item and long text is truncated; nothing else is changed. API keys and tokens are masked.

  • YouTube Data API v3 channels: channel lookup
  • YouTube Data API v3 playlistItems: list a channel's uploads
  • YouTube Data API v3 videos: duration and statistics (the trend readings)
  • Spotify Web API token: client-credentials access token
  • Spotify Web API search (type=track): song metadata — the main call
  • Spotify Web API search (type=artist): artist picker
  • Spotify Web API search (type=album): label crawl (manual, legacy)
  • Spotify Web API albums/{id}: full album with tracklist
  • Spotify Web API tracks/{id}: single track (ISRC)
  • Spotify Web API artists/{id}/albums: seed artist releases
  • Deezer API track/isrc:{ISRC}: Deezer rank
  • Errors 429 / 403 / 400

YouTube Data API v3

Base URL https://www.googleapis.com/youtube/v3. Auth: API key (key= parameter; masked as *** in everything the app stores). Daily quota 10,000 units; the app uses about 30 units per sync.

When it is called
Every YouTube sync (every 6 h). Reads each channel's “uploads” playlist (UU… = UC… id) newest first, 50 per page, and stops at the first page older than the window; incremental after the first run.
Code

Cost
1 unit per page of 50
Request

Spotify Web API

Base URL https://api.spotify.com/v1. Auth: client credentials (no user login). The app is in Spotify development mode: search pages hold at most 10 results, batch endpoints return 403, and label, popularity, followers and genres are no longer returned.

token: client-credentials access token

When it is called
Before the first Spotify call of a run, and again when the token expires (1 hour). The token is never stored or shown.
Code
lens/spotify.py _fetch_token()
Cost
not counted
Request
POST https://accounts.spotify.com/api/token (Basic auth = client id:secret, body grant_type=client_credentials)
Captured URL
POST https://accounts.spotify.com/api/token (grant_type=client_credentials)
HTTP status
200

Fields the application uses

FieldStored as / used for
access_tokenBearer token for the calls below (kept in memory only)
expires_inwhen to refresh
Sample response
{
  "access_token": "BQD…(redacted)",
  "token_type": "Bearer",
  "expires_in": 3600
}

When it is called
Songs step of every pipeline run: one call per YouTube song without a Spotify link. A miss is rechecked after 3 days.
Code

Cost
1 call per song
Request
GET /search?q=track:"{song title}"&type=track&market=IN&limit=10&offset=0
Captured URL
https://api.spotify.com/v1/search?q=track%3A%22Kaal+Mulaitha+Poovae%22&type=track&market=IN&limit=10&offset=0
HTTP status
200

tracks.items[].id / external_urls.spotifyplatform_item (platform = spotify) and the Spotify link
namecompared with the YouTube song title (deterministic score)
artists[].name / idartist table, and the artist-match signal
duration_msduration-match signal
external_ids.isrctrack.isrc; also the key for the Deezer lookup
album.name / album_type / release_date / idrelease table; release_date decides “new” vs “catalogue”
explicittrack.explicit

Error responses the application handles

429 QUOTA_EXCEEDED: daily quota for an endpoint group

Album and track lookups are currently blocked (Retry-After ≈ 23.6 h). Search keeps working. The app records the retry time on the Sources page and does not retry until then.

https://api.spotify.com/v1/albums/0ws4BhBlmjvbpnmseHCEP0/tracks

{
  "error": {
    "status": 429,
    "message": "Too many requests",
    "reason": "QUOTA_EXCEEDED"
  }
}
